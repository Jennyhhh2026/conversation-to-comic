# 可选文章与公众号排版

仅在需要共创文章或输出公众号稿时读取。

## 访谈粒度

不要一次抛出大量表单问题。最影响方向的是：谁读、希望读者得到什么、谁的口吻。再按需要问：现场与洞察比重、希望保留的人/细节、实名引用范围、篇幅、外部资料范围。用户已给充分要求时直接创作；“先问我”则先交流。

## 多人叙事

- 主持人是串场视角，嘉宾的工作和问题是内容主体。
- 每位主要发言人保留独有贡献：工具、案例、问题、失败、方法或合作意愿。提问者不应只充当衬托。
- 不把气氛友好写成全员观点一致。保留有益分歧，解释不同任务、标准、经验可能导致不同感受，不硬凑一句万能解释。
- 小白友好靠即时解释术语、具体场景和因果关系，不靠删掉行业信息。
- 反常识观察用“这个案例提醒我”“我想继续验证”限定范围。不要把一次付费写成商业模式已跑通，也不把机构许可、个人资格与允许开展的业务混为一谈。
- 结尾从发生过的事情过渡到合作邀请；未完成的收购、筹备、合作写成探索/意向，不写成已实现。

## 公众号 HTML

按用户需求生成可独立打开的 UTF-8 HTML 和可编辑文本稿。正文样式尽量内联，简洁段落、有限强调色、适当留白；避免把文章排成密集仪表盘。

标题、操作栏和正文明确区分。“复制正文”复制渲染后的富文本，不只是源码；支持时使用剪贴板 HTML 与纯文本两种 MIME，权限失败时提供“选中正文 + 手动复制”路径。提示在公众号编辑器预览，不声称所有平台必然完全保留样式。

不要将脚本、复制提示或工具操作栏带进正文。未做真实粘贴测试时，只报告已生成排版文件，不报告已验证公众号兼容性。

## 可复用的改编示例（虚构）

原始实践：运营者管理多个账号，不想在新对话里重复传授方法。

叙述：刚培训完的同事，换个会议室又问公司做什么。

洞察：用户在意的不只有单次生成质量，还有已有经验能否持续复用。

分镜：三台电脑、一位疲惫运营者、一本空白机器人笔记；台词“换个账号，又要从头教？”

这个示例演示压缩方法，不要求所有漫画套用同一个笑点。
